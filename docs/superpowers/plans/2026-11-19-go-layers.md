# Go layers and abstractions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reshape `src/go` into the seven layers of `src/go/ARCHITECTURE.md`: parsing returns typed rows; `datamodels` owns rows, builders, log sources and refs; every backend sits behind `storage.Reader` / `storage.Writer`.

**Architecture:** The work goes bottom-up: get the build green, then `edid` → `catalog` → `datamodels` → `fileparse` → `storage` + `convert` → `cmd/sfg`. Each storage backend is wired into the CLI in the same task that builds it, so every task can be verified by running the real `sfg` binary on real fixtures, against a local warehouse and against AWS Glue.

**Tech Stack:** Go 1.26, arrow-go v18, iceberg-go v0.7 (SQLite local catalog, Glue), gnsstools (RINEX, observation epochs), cobra, bash/awk for verification, Python 3 / pyarrow for the one Python caller.

**Spec:** `src/go/ARCHITECTURE.md`

## Global Constraints

- **No commits.** Never run `git commit` (the user commits). Leave all changes in the working tree; the controller snapshots each task as a patch for review.
- **No unit tests.** The only `_test.go` files allowed are the existing `cmd/sfg` tests and the integration test `src/go/dev/verify/verify_test.go` (Task 4b). Verify every task with `go build ./... && go vet ./...`, `go test ./cmd/sfg/`, `dev/verify/verify.sh` (CLI, Task 1) and, from Task 4b on, `go test ./dev/verify/ -count=1` (library; add `-glue` when the task touches Iceberg). A task that changes a library API the integration test calls must update the test.
- **Glue runs only against development databases.** Every Glue command uses `--database-prefix dev_` and `--warehouse "$SFG_DEV_WAREHOUSE"` (an `s3://…/sfg-dev` prefix the user provides). `verify.sh glue` refuses to run if either is missing. Never write to Glue without the prefix.
- Glue settings for this project: `export SFG_DEV_WAREHOUSE=s3://test-sfg-api/sfg-dev AWS_REGION=us-east-2`. Production `gnssa_l0` lives under `s3://test-sfg-api/gnssa-test/`. Never write there.
- Glue needs an active AWS SSO session (`aws sts get-caller-identity` succeeds) and `AWS_REGION` set. If either is missing, stop and ask the user. Don't skip the Glue run.
- Imports point downward only: `edid` ← `catalog` ← `datamodels` ← `fileparse` ← `storage` ← `convert` ← `cmd/sfg`. Packages under `fileparse/<format>` never import Arrow or `storage`.
- Every Writer takes Arrow, including RINEX.
- Code outside `datamodels`/`catalog` refers to tables only through the declared ref vars (`datamodels.L0TWTT`, …).
- Log sources are listed once, in `catalog.TableDef.Sources`, in `datamodels`.
- The Iceberg writer replaces each stream's rows over the batch's time span and records the source path and SHA-256 in the snapshot.
- Exit codes stay `ExitOK`=0, `ExitFatal`=1, `ExitUsage`=2, `ExitPartial`=3. Bump `ResultSchema` if the `--result` JSON changes.
- Run Go commands from `src/go`. Fixtures are in `tests/data/` (repo root): `test_20260331_174553_00030_NOV770.raw`, `test_gcc1_20250821_205746_00062_NOV000.bin`, `test_gcc1_20250822_DFOP00.raw`.

## Review Focus

1. **Re-ingesting the same files** leaves row counts unchanged, locally and on Glue. This is the `verify.sh` check `reingest` (Task 1).
2. **No `stream_edid` or row count changes** across the refactor, including NOV770's second antenna (`_1`). `verify.sh` output must equal `dev/verify/baseline.txt` after every task.
3. **A `--log-source` that no table lists** (e.g. `TCVR00.NOPE`) exits with code 2 before any file is read. This is the `verify.sh` check `bad-log-source` (Task 6).
4. **RINEX from Iceberg with two antennas in the table and no `--log-source`** exits non-zero, names both streams on stderr, and writes no files. This is the `verify.sh` check `rinex-two-streams` (Task 10).
5. **One corrupt raw file among good ones** fails only its own input. The others are written, and the exit code is 3 (`ExitPartial`). This is the `verify.sh` check `partial` (Task 7).

  - `type Batch struct{ Ref catalog.TableRef; Table arrow.Table; Source *catalog.SourceFile; Err error }`
  - `var ErrSkipped = errors.New("not a recognised raw file")`
  - `type Reader interface{ Tables() []catalog.TableRef; Read(ctx context.Context, sel Selection, yield func(Batch) error) error }`
  - `type Writer interface{ Accepts(catalog.TableRef) bool; Write(ctx context.Context, b Batch) ([]Output, error); Close() error }`
  - `type Output struct{ Ref catalog.TableRef; Path string; Rows, Bytes int64 }`
- `storage/raw`: `func NewReader(inputs []string) (*Reader, error)`. Inputs are files, globs or directories, expanded in sorted order.

  - An unknown file type yields `Err: ErrSkipped`. A parse failure yields `Err: <that error>`.
- `storage/files`:
  - `type Format string`; `const CSV Format = "csv"`, `Parquet Format = "parquet"`

- `convert`: `func Run(ctx context.Context, r storage.Reader, w storage.Writer, sel storage.Selection) (*Result, error)`.
  - Before reading, it returns `*UsageError` when any ref in `sel.Tables` (or `r.Tables()`) fails `w.Accepts`.
  - Batch errors are recorded as input status `failed`, `ErrSkipped` as `skipped`, and the run continues.
  - After `w.Close()`, it appends `Outputs()` when the writer implements `interface{ Outputs() []storage.Output }`.
  - The exit code is `ExitPartial` when at least one batch failed and at least one succeeded.
